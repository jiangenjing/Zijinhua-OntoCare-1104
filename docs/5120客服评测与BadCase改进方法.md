# 5120新版智能客服：评测与Bad Case改进

## 参考方法与本地对应

Palantir AIP Evals的逐题调试视图展示输入输出、执行轨迹、错误和评分器结果，并支持对失败用例进行根因分析。其实验功能允许固定用例，改变模型、Prompt等参数进行对照。这些是本轮采用的方法参考；本地实现没有使用Palantir托管评测服务。

- https://www.palantir.com/docs/foundry/aip-evals/analyze-run-results
- https://www.palantir.com/docs/foundry/aip-evals/experiments

RAGChecker将检索和生成分开诊断，强调细粒度指标与实际错误分析。本轮借鉴这种分项思路，不声称运行了RAGChecker框架。

- https://arxiv.org/abs/2408.08067

## 实验设计

1. 复制当前服务代码、Prompt、Skill、数据、本体与数据库，形成冻结快照。检测到原5120内存实现与磁盘实现已有版本差异后，将5120统一到冻结快照，再开始正式计分。保留服务runtime、数据集、代码、Prompt和评分器哈希。
2. 固定原548题：480知识、48边界、16订单、4组多轮。原题、参考答案、期望决策和主Judge规则不变。
3. 同一冻结实现运行两组完整548题：关闭体验Prompt/Skill的控制组；开启体验v1、使用真实流式协议的新版组。相同题目的两组执行顺序交替，降低系统负载与缓存顺序的偏差。共享快照缓存仍使延迟不等同于严格冷启动实验。
4. 单列历史原版与历史候选，仅作历史回归参考。历史基础实现和本轮存在差异，不能把分数变化全部归因于Prompt。
5. 查看失败题和“任务通过但忠实度偏低”的题，读取用户输入、实际答复、引用、完整检索列表、业务工具结果、代码决策、模型状态和输出校验。
6. 对Bad Case追加独立调用的诊断：补充官方正文与检索证据包，区分真正无依据建议与主Judge未见到完整证据造成的评分疑点。这个诊断不替换主评分，不改变Gold。
7. 依据共性原因修改对应环节，冻结候选，再完整运行548题，报告修复、退步和仍失败的逐题清单。

## 本体客服的归因与修复方式

| 层次 | 核查内容 | 合适的修复 |
|---|---|---|
| 对象识别 | 工程型号、可售SKU、配件编号是否混在一起 | 有证据的别名/对象映射；真实冲突保留澄清 |
| 关系/范围 | 节点关联是否被误当成正文适用证明 | 保留型号范围约束；图关联只用于导航 |
| 检索 | 需要的证据是否被召回，直接相关条目是否靠前 | 修改查询理解、作用域过滤、排序；不注入标准答案 |
| 生成 | 是否漏掉条件、添加无依据的操作、扩大因果强度 | 修改Prompt/Skill，优先最直接证据，保留条件，减少额外建议 |
| 决策 | 已有订单/销售方工具结果是否进入正确分支 | 修改确定性路由，不能只要求模型违背错误代码分支 |
| 历史状态 | 是否重复问过的信息、重复已做检查、混用旧产品 | 修正状态继承与产品切换规则 |
| 数据/Judge | 合成问题含范围冲突；Judge缺官方正文或别名证据 | 保留原始评分，另列诊断与人工复核队列；不通过改标签美化主结果 |

## 指标解释

- 任务通过率：原主Judge正确性、安全性、历史检查，加期望决策及代码校验；缺评和接口失败不计为通过。
- 知识首条命中：检索第一条命中Gold或同内容来源组的查询比例，分母为480个知识题。未检索按未命中计。它不是回答正确率，也不是要求全部相关文档的集合召回率。
- 原子声明忠实度：独立LLM Judge判断的支持声明数/总声明数，同模型家族、无独立人工背书；官方补充正文未进入历史主Judge上下文的情况另行标记。
- 耗时：端到端P50/P99、图检索和知识检索延迟。流式首条等待状态不是模型首token，另记录首段已校验答复时间。
- Token：真实记录的回答和检索模型消耗、Judge消耗；未获取计费单价时不编造金额。
- 真实解决率、CSAT、真实转人工率、重复咨询率需要生产闭环，离线548题不能证明这些指标。

## 可信边界

这些548题早已用于诊断，全部属于已见回归。它们不能再充当新盲测泛化证据。仅4组多轮也不足以代表真实多轮复杂度。主Judge与生成器属于同一模型家族；合成参考答案和模型评分仍需要客服专家抽检。没有进行RLHF、DPO或模型权重微调。

本轮候选基于前144道已运行问题中的失败模式和代码路由诊断提前冻结，随后完整运行548题；其余基线及控制组继续完整执行，不依据最终548结果临时改动该候选。冻结时采用的6道失败题与修改文件哈希见 candidate-changes.json。

本轮额外固定12道同题运行实际Ragas指标，三组上下文均包含检索原文及引用的官方正文；它与历史仅原文上下文的Ragas不直接相减。不生成所谓通用Ragas综合分。

## 候选筛选与本体对象角色修复

v2加长Prompt并修正路由，完整548题通过525题；不能因为目标失败题改善就视为全量更好。v3复用已有证据校验器，在失败集中与固定正常题组成的40题专项中，任务23/40→25/40，但声明忠实度72.95%→69.36%，HTTP P50约8.75s→13.77s；不能视为整体胜出，也没有将其上线。40题是定向诊断样本，非总体准确率。

v4保留v1的Prompt/Skill正文，并修正对象标识角色：客户明确一个已知主机PN时，若同范围原始资料同时明确某完整长编号是法兰/配件，则该编号不再因SKU前缀匹配而被当作第二个主机。原提问仍完整交给检索；未知主机PN、两个真实主机PN继续澄清。不硬编码某道题的回答，也不更改来源适用PN。

## 本轮选用规则与复现

在任务通过率、声明忠实度、安全标记和代码校验均不差于v1的候选中，按任务通过率优先、声明忠实度作同分取舍。选择基于已见548题，不等于新盲测或显著性证明。v2与v4完整结果均保留，40题校验器试验单列。

5120使用独立冻结发布，不影响5112。启动入口为 `.venv/bin/python scripts/serve_customer5120.py`，读取 `local/customer-service-v2/experience548/deployment.json` 选择已评测快照。切换后真实流式接口的runtime与Prompt/Skill哈希再次核对。

图搜索仍为现有按型号约束的两跳BFS，检索/重排算法未在本轮修改。原始召回首条命中可能受查询改写、模型重排和缓存并发的随机性影响，不把细小差值直接归因为Prompt或新检索算法。所有延迟结果亦受并发负载和缓存影响，不能代替固定负载压测。
