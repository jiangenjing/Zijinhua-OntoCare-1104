# ActionType：提交本地人工复核

执行页：`http://127.0.0.1:5112/ontology/actions`。本体工作台左侧提供入口；四类类型目录中的 `submitForReview` 也可进入执行页。

已注册的行为契约保存在 `actions/submit-review.json`。执行器是 `ontocare/actions.py` 中的固定处理函数，不解释任意 `${...}`，也不执行用户上传的代码。

一次提交需要工单对象引用、至少六字符的理由和幂等键。角色与用途从服务端上下文取得，不接受客户端传入角色。当前使用固定本机演示操作员，未接入生产身份认证、账户权限管理和工单行级授权。

校验要求工单存在、当前本地处理状态允许、没有重复的待处理复核任务。事务统一完成以下内容：

1. 更新本地工单处理状态为 `PENDING_REVIEW`（待复核），增加处理版本。
2. 创建 `ReviewTask`（复核任务），记录工单、理由、操作员、时间与审计标识。
3. 创建 `needs_review`（提交复核）关系。
4. 记录 `REVIEW_REQUESTED` 事件到本地事件表，不投递外部消息系统。
5. 保存成功审计和幂等回执。

所有业务写入、成功审计和回执在同一个 SQLite 事务中提交。中途失败回滚业务写入，再记录失败审计。重复提交相同幂等键和参数返回原回执；同键不同参数拒绝；不同请求并发操作同一工单，也不能重复创建待处理任务。

原始 Excel、源工单和静态知识版本不变。运行期状态单独存于忽略提交的 `local/actions.sqlite`，由本体管理投影显示；它不是模型学习出的知识，不参与 FAQ 检索。选择旧知识版本也会显示当前运行期工单状态，而非历史状态回放。

接口：

- `GET /api/action-types`：动作定义和本机演示身份。
- `POST /api/actions/submit`：执行已注册的本地动作，只接受本机同源请求。
- `GET /api/actions/history`：最近 20 条成功／失败审计。

本地复核任务不等于真人已接单，也不执行退款、换货、订单变更或邮件发送。本轮没有实现流程结束、关闭复核任务、审计回滚或通用 ActionType 引擎。

验证：`tests/test_actions.py` 覆盖真实变更和图投影、幂等与同键冲突、角色和用途权限、错误引用、客户端角色注入、事务中途失败、并发重复提交、跨源及非本机请求。连同管理界面和客服相关回归，本轮 92 项检查通过。
