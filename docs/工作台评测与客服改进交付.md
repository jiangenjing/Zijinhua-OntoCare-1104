## 三类指标与判定

- 效果：所有计划案例的任务通过率、模型完成率、首条命中Hit@1、资料集合Recall@K、MRR、五维Judge和Ragas四分项。
- 效率：实际HTTP发送至完整JSON的平均/P50/P99、图遍历耗时、输入/输出token；推理与裁判成本分开。未测TTFT；无核实价格所以金额成本待测。
- 业务：生产解决率、实际转接率、CSAT、重复咨询率缺少结果标签，不能由Judge替代。新增本机自愿反馈采集，按会话最新反馈去重，作为演示反馈单独展示。

五维Judge各0—2分：事实与型号、证据支持、步骤与历史、业务条件与边界、中英文清晰度。通过需≥8/10、任务满足、关键维度非零、所有轮次模型完成与硬检查通过；失败和通过都有理由。裁判与客服同为DeepSeek网关标识DeepSeek-V4.1-Flash，独立调用仍有同源偏差。

Hit@1判断第一条是否属于任一接受来源；资料集合Recall@1计算第一条覆盖全部gold资料集合的比例，多个标准来源时不同于Hit@1。本轮保留两个口径，不因失分放宽旧标签。

## 消融

固定18个已见场景，各消融一次，对照改进后第一轮同样场景。

| 处理 | 通过/场景 | 通过率 |
|---|---:|---:|
| full | 18/18 | 100.00% |
| no_skill | 16/18 | 88.89% |
| no_ontology | 18/18 | 100.00% |

no_skill在隔离副本中同时清空Skill文字并关闭状态继承；仅切换原有no_skill标记并不等于去掉所有Skill Prompt。no_ontology移除范围/图上下文/本体工具的组合能力，并非单独BFS因果消融。小样本不能证明本体或Skill普遍有效。

本轮去Skill的两项失败均为多轮流程决策：内容Judge仍给10分并认为答复满足，但预期应建议人工核查，实际返回普通answer，因此程序门控不通过。去本体在这18题没有降低通过率，本体的问答质量增益在该小样本未得到证明。

## 改了什么，如何构成改进闭环

| 层 | 本轮实际变化 |
|---|---|
| 工作台接线 | 默认客服由旧customer_agent切到已测agent实现；真实页面与评测目标对齐 |
| 检索 | 默认采用此前的中文保真改写＋E5标题/正文/BM25加权＋保守证据核验；新FAQ问题匹配候选验证不佳被拒绝 |
| Prompt和校验 | 沿用已测Skill、未知型号澄清与一次结构修复重试；并非每次回答另训练模型 |
| 页面 | 新增运行版本、图路径/约束、最新候选记录、三次重复结果、五维理由和自愿反馈 |
| 模型参数 | 本轮未执行RLHF、未训练DeepSeek权重。此前小型重排训练失败记录保留 |

当前图搜索为型号范围内两跳BFS，最多30概念/6证据，从检索知识节点出发，产品中心不继续扩散。返回路径、映射、约束给模型；不是社区检索，也不是通用OWL逻辑推理。售后条件判断仍由代码规则校验。

失败轨迹→检索/规则/Skill/来源归因→局部候选→开发验证→配对回归→独立确认→采纳或拒绝。当前属于工程协助的受控改进，不声称主模型、Schema或改进器已能全面自主递归修改。

## 为什么98.15%仍不能当作真实正确率

该数值是按既定规则计算的机器裁判流程通过率，尚未经过独立人工校准。T2071多楼层案例原表第123行只有外部参考链接；同一来源6次执行被判2次通过、4次未通过，一条通过回复补充了当前可见正文未支持的操作。原分保留，同时标为来源正文不足、工具访问缺口与裁判一致性待复核。不能用强迫生成步骤的Prompt补齐证据。

若仅将这一家族全部视为未确认，敏感性计算为210/216＝97.22%；这不是完整人工纠偏，也不是真实解决率。其他未审案例仍可能有误判。人工20组抽检与6组忠实度争议保持待复核。
