# 智能客服对话界面与流式图谱

入口：本体工作台侧栏“智能客服”，或本体地图标题区“进入智能客服”，跳转 `/service#assistant`。

界面参考用户提供的比赛截图：浅色双栏、左侧聊天、右侧对话本体。原参考站点未能通过网页读取工具访问，因此以截图和现有本地产品结构为依据实现；没有复用其回答内容。

## 实际交互

- 左侧连续聊天，Enter发送、Shift+Enter换行；发送过程中禁止重复发送和新建会话。
- “猜你想问”根据返回的产品型号或订单对象更新，作为可编辑提问建议，点击后填入输入框，不自动发送。
- “试查样例订单”展示比赛订单例子，不能表示订单归属于当前用户；核查真实归属仍是业务缺口。
- 新对话清空会话、补充字段、对话图谱与来源。支持查看英文答复、提交本机解决情况和满意度反馈。
- 右侧图谱每轮使用实际返回的检索节点、关系、引用知识、订单商品和包裹更新；节点可点击查看依据并定位答复。本轮/全部对话切换，最多显示32个对象并标明截断。
- 订单“记录包裹”不表示每个包裹的内容已知。服务判断的上下文连线使用虚线，不冒充已批准售后动作。产品知识关系来自现有按型号限制的两跳BFS图检索。

## 流式输出的具体边界

`POST /api/chat/stream` 使用与 `/api/chat` 相同输入校验及当前服务 Agent。SSE依次返回status（接收/等待）、evidence（已完成的返回包）、delta（已校验答案的文本分段）、done；失败返回error。模型调用、来源约束、输出校验完成后，才将答复逐段呈现。没有接入供应商未校验token直出，不把等待提示冒充实际工具完成事件，也不将该路径的首个status延迟当作模型首token时延。

图谱在evidence事件到达时更新，与后续文字分段显示联动。它不是持续修改业务本体的写入动作。

## Prompt与Skill

新界面请求绑定独立 `customer-experience-v1`：在现有响应契约上追加 `prompts/customer-experience.md`，在专用排障/物流/售后/澄清Skill上追加 `prompts/skills/customer-experience/SKILL.md`。两者内容均计入实际返回的Prompt/Skill哈希。

新增规则强调：最新问题优先、直接简洁、连续对话复用信息、不重复检查、不把相邻资料当证据、不输出内部实现、订单逐商品区分、缺条件先核验、没有执行回执就不宣称售后执行成功。模型仍遵守原双语JSON与引用契约，界面负责显示和建议。

普通 `/api/chat` 不主动绑定新界面体验配置；历史评测文件未改。现有线上基础Agent曾由其他开发更新为SourceActionAgent，本轮沿用当前运行实现，不声称沿用历史548题评测的完整代码。新体验配置不继承历史97.08%通过率，也未做全548题重新评测。本轮验证以新增流式契约测试、既有对话和服务规则回归、真实模型冒烟、桌面和移动界面检查为范围。
