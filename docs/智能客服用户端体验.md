# 智能客服用户端体验

本次在重建版工作台增加用户端入口，沿用比赛截图的简洁白色／深蓝双栏风格。原公开仓库与 Render Demo 未修改。

## 打开与提问

- 本体工作台：`http://127.0.0.1:5112/ontology/manager#topology`。上方“智能客服 · 用户端”进入新页面。
- 用户端：`http://127.0.0.1:5112/service`。左边聊天，右边是本次实际查询到的产品、知识、订单与条件关系。
- 点击推荐问题会填入输入框，确认后发送；“分析这笔订单”会新建对话并查询所选订单，避免继承上一笔订单的上下文。
- “猜你想分析哪笔订单”提供全部 16 笔赛题订单；默认显示 4 笔，可展开全部。卡片来自实际源表购买日期、SKU、商品描述与状态，不移用别的产品图片，也不代表个人购买记录。
- 可直接问“我的 E25 报错误码3212，应该先检查什么？”，随后说明“滚筒缠绕异物已经清理过了，但仍然报3212”，测试历史步骤继承。
- 型号／SKU、订单、购买国家、销售方是选填资料。订单归属、实际收货和售后资格仍需独立核验。

## 回复与图谱如何同步

1. `/api/chat/stream` 先返回收到请求的状态。
2. Agent 完成对象识别和实际查询时，返回对应进度事件；这些是完成的工具步骤，不是模型思维过程。
3. 检索完成后就返回图谱预览。此时资料是候选，不能当作最终引用。
4. 按现有来源、型号和业务边界规则检查生成结果，然后发送最终依据与答复片段。
5. 图谱切换为最终引用和业务查询结果。实际错误和保底状态保持可见，不伪装成模型成功。

这是 **SSE 实时进度＋图谱预览＋校验后分段答复**，不是上游模型 token 直接透传。检查前不会向用户发送未经校验的正文，也没有把动画时间计为模型首 token 耗时。

节点与边支持点击、键盘 Enter／空格查看；节点可拖动、连线可调整走线，空白处拖动画布、滚轮缩放。“适配视图”恢复默认布局，“展开对象”展示更多查询对象，“全部对话”合并当前会话真实返回的对象；详情按钮可回到对应回复。布局操作不修改业务数据。

实线代表资料记录的关系；虚线代表本轮上下文或候选。例如准确订单号可关联商品行，商品行可关联实际 SKU，物流行与商品行的来源对应**不证明包裹内实际包含该商品**。SKU 前缀不能自动证明型号关系。右侧显示中文类型与说明，英语原始知识标题和正文在详情中保留；节点未翻译时用来源行定位，避免凭空翻译业务含义。

## Prompt、Skill 与后端边界

每次用户端请求叠加 `customer-experience-v1`，保留基础客服协议与当前专用 Skill：

- `prompts/customer-experience.md`：先答当前问题，限制无关步骤；不输出内部工具／图谱指令，不编造来源或审批回执。
- `prompts/skills/customer-experience/SKILL.md`：产品澄清、故障排查、物流和售后场景的客户表达；跳过已完成检查，区分客户陈述与核验结果，保留证据缺口。
- Prompt 与 Skill 内容指纹随处理轨迹保存，可核对实际使用版本。

检索排序、来源绑定、型号过滤、受限图遍历、六次工具预算和业务规则沿用重建版；本次没有复制比赛机器人的回答逻辑，也没有调整评测口径。图谱是实际后端查询结果的只读投影，不是模型随意绘制的关联。

模型仍由服务端已有本地配置连接 `DeepSeek-V4.1-Flash`。网页只读取模型名称和配置状态，密钥不进入 HTML、JavaScript、订单卡片或测试报告。

## 复现

在项目目录，使用本机已有配置启动（不要把配置提交仓库）：

```sh
ONTOCARE_LLM_CONFIG="$PWD/local/deepseek-config.json" .venv/bin/python -m ontocare.cli serve --port 5112
```

```sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_customer_ui.py
```

后一个命令会真实调用模型两次并记录 SSE 时序、引用、检查结果、状态继承及图谱规模；不修改正式评测集或发布版本。
