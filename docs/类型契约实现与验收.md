# 类型契约：从解释性定义到本地可执行实现

本次补齐工作台四类类型契约中原先的9个缺口：3个对象、2个关系、3个动作、1个函数。增加创建任务入口是使这套契约可执行的必要前提。现有只读对象与来源图继续按原流程导入，不开放对原始Excel及已发布语义版本的任意编辑。

## 四类契约具体做什么

| 契约 | 当前实际实现 | 核查方式 |
|---|---|---|
| Object Type | ServiceTask 服务任务、CheckObservation 检查观察、ServiceRequest 本地服务复核申请实际入库 | 类型卡片的“实例/记录”显示真实对象；无操作时允许为0，不生成假实例 |
| Link Type | HAS_OBSERVATION、REQUEST_HANDLES_TASK，以及任务到案件/源工单、观察到步骤、申请到人工待办的明确关联 | 类型卡片与实例拓扑显示实际端点、动作编号和来源 |
| Action Type | createServiceTask、recordCheckResult、updateSessionCheckState、submitManualReview的固定处理器 | 真实输入校验、角色/用途/任务范围、适用步骤、状态与版本检查、幂等、事务回滚、事件和审计 |
| Function Type | 11个直接调用的只读函数；suggestNextCheck已独立注册；advanceServiceCase仍由现有客服动作调用 | 函数参数Schema、调用入口、实际输出及输入/输出哈希记录；只读入口禁止写函数 |

“全部实现”限定于工作台当前声明的本机功能。不是已部署Palantir Foundry，不执行任意JSON表达式，不执行真实退款、换货、物流或外部坐席分配。ServiceRequest的COMPLETED只表示本地人工复核已完成，不表示售后已经执行；不提供财务APPROVED状态来暗示退款批准。

## 数据与职责

- ServiceCase是一次会话案件；ServiceTask是其中一个已确认型号、错误码上下文的处理任务。同一案件换型号或错误码时创建新任务，旧观察保留，不能把旧型号的检查继承给新型号。
- 从真实工单创建的任务保留源工单引用，另存本机处理案件；原63封首封工单不被修改，也不伪装成新增真实客户或新增结案。
- CheckObservation记录具体步骤、结果、客户原话、来源版本、时间和证据引用。客户报告始终是REPORTED；相互冲突的报告保留历史并标记CONFLICT，不变成物理核验。
- recordCheckResult的明确完成结果同步至对应客服会话，后续Skill可跳过已报告完成的步骤；若客户改口未执行，会撤销当前完成标记并保留旧观察。
- submitManualReview实际创建ServiceRequest、关联任务并写入现有人工待办。重复申请复用有效编号。人工审核入口中的补信息、拒绝和本地审核完成同步到申请与任务。
- Task创建、检查与复核动作使用同一套本地事务处理器；客服自动创建任务也留下Action审计。

## 查询与操作边界

suggestNextCheck限定已确认型号与错误码，从发布且客户可见的来源中取步骤，并复用现有SourceActionAgent的正文支持检查。完成步骤全部排除后返回MANUAL_REVIEW，无依据或缺上下文时返回NEED_CONTEXT，不编造新动作。

对象和关系由固定代码写入。数据库事务保护对象、关系、事件及回执；会话检查同步与本机业务写入通过同一SQLite连接的附加数据库事务提交。审计是本机记录，不宣称防篡改存证。

身份来自服务端本机演示操作员配置，客户端不能提交角色、verified或approve字段来提升权限。校验任务归属与可选任务授权列表；跨站或远程写入拒绝。此模式不是生产身份认证，生产部署需接入真实身份、最小权限和后台系统。

只读函数允许保存调用审计，但不修改业务事实。密钥仍只保存在本机；函数入口不返回密钥。模型配置缺失时不因读取可选配置文件而崩溃，检索如实使用可用回退。

## 如何使用

1. 打开 `http://127.0.0.1:5112/ontology/manager#object-types`，选择一个类型，点击“实例/记录”或执行入口。
2. 打开 `http://127.0.0.1:5112/ontology/contracts`。从已有工单创建任务，或先在智能客服提问“我的T2353报错误码3212”，再刷新选择自动生成的任务。
3. 计算来源支持的下一步。填写明确的客户原话，例如“已经检查并清理滚筒异物，问题仍然存在”，保存观察。
4. 查看完成步骤继承、真实对象和关联；填写至少6字理由提交复核，取得实际本地申请与人工待办编号。
5. 在 `/workflow/human` 查看和处理本地复核；实际审核结果会同步到ServiceRequest。
6. 右侧函数表单可调用型号识别、观察识别、下一步检查、本体解析、知识检索、订单、经销商、服务规划、决策规则、意图识别和售后前提检查。

输入框中的错误码查询不擅自修改来源事实；原始资料不足时保持待核查，而不是用“功能已实现”冒充“业务事实已核验”。
