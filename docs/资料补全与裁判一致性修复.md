## 修复的真实问题

1. **多楼层清洁只有链接。**原资料第123行、`qa-6c5ab718a89d` 没有具体操作正文。补入原链接对应的官方文章后，模型可给出实际步骤，并显示官方 URL 和哈希。另一个视频页继续标为未解析，没有用视频标题编造步骤。
2. **部件提及被误当成检查动作。**原图谱的词项匹配可能把供水诊断中的“roller mop”连到通用滚筒清理。修正版在采用图关系前检查原文是否实际描述相应动作，避免因名词出现就触发除毛发等通用步骤。
3. **已完成步骤的继承。**初版动作筛选漏掉 `restarting`，多轮案例虽然文字建议人工核查，代码决策却还是普通回答。已修复词形识别并保留这轮失败，不把 Judge 的10分当作工作流正确的证明。
4. **条件被强化。**生成 Prompt 增加“如果满足条件才判断”的约束，禁止把诊断步骤说成确定或最可能原因。该约束没有消除所有问题，仍需逐案复核，不能宣称已经杜绝幻觉。

图搜索仍为原有型号范围内两跳 BFS；本轮没有新增社区检索、OWL 推理或主模型训练。旧图的全部关系也没有因此自动获得事实认证。动作采用的是来源筛选与现有 Skill 状态，无法确认时保持信息缺口。

## 同一输入的候选结果

父版是上一轮已改进的 V2 客服 Agent，不是最早的标题检索版本。每个候选使用同一72个已见场景、原 gold、原 Judge，均保存实际 HTTP 回复。后三个候选复用同一批已保存的父版回复，不重新抽父版好分数；不是独立测试，也不能据此推断时延的因果变化。

| 实现 | 机器流程通过 | 模型完成场景 | Ragas忠实度，固定12请求 | 决定 |
|---|---:|---:|---:|---|
| 本轮冻结父版 | 71/72，98.61% | 72/72 | 91.50% | 对照 |
| 官方正文＋条件Prompt | 71/72，98.61% | 72/72 | 89.19% | 忠实度下降，拒绝 |
| 来源动作筛选初版 | 71/72，98.61% | 72/72 | 93.45% | 存在词形导致的流程回归，拒绝 |
| 增加模型支持性检查 | 69/72，95.83% | 70/72 | 98.15% | 误拦截、完成率回归，拒绝 |
| 来源动作筛选修正版 | 71/72，98.61% | 72/72 | 92.77% | 本机试用，未通过独立验收 |

Ragas仍使用0.4.3原评测器。固定12请求来自6个来源，使用实际提供的原文、型号、用户状态、Skill与官方正文；父版相同输入及判分原样复用。没有把调用失败删掉，也没有把不同回答中更高的分数挑出来替代旧分。

修正版相比父版：**1个场景改善、1个场景退步，总通过率没有提升**。改善是中文多楼层案例；新退步是 `kb-fb1e244c982076:zh` 的 T2071 碰撞问答，保留7/10与原理由。忠实度均值增加1.27个百分点，但按来源聚类的95%区间约为 **−3.98至+7.31个百分点**，不能证明总体无回归。

## 检索实验与90%门槛

| 配置与范围 | Hit@1 | 资料集合Recall@1 |
|---|---:|---:|
| 当前客服，同一300题已见回归 | 87.00% | 85.70% |
| 细分正文分段，固定验证300题 | 92.67% | 89.44% |
| 官方正文参与重排，固定验证300题 | 93.67% | 90.44% |
| 官方正文参与重排，同一300题已见回归 | 86.33% | 85.04% |

细分段候选仅在开发集拟合四个全局权重，验证集不拟合。正文参与重排虽然在验证集超过90%，历史回归反而低于当前版本，因此也拒绝，没有用验证成绩冒充独立成绩。当前实际检索 ID 顺序复算仍是87.00%／85.70%，说明本轮主要改善正文可访问性与动作采用，没有取得可认证的检索提升。

`Hit@1` 表示第一条命中任一 gold；集合 Recall@1 使用全部 gold 作分母，两者继续分别报告。原多 gold 分母不缩小、标准来源集合不放宽，错误题不删除。

## 裁判不一致怎么处理

保持原五维0—2分、总分≥8及原硬检查不变。18份保存的原回复各复评3次，16份通过判定一致，2份出现分歧：判定一致率88.89%。分歧项仍待人工裁定，不按多数票提高旧通过率。初次脚本把案例ID误作来源家族ID的非目标样本审计单独保存；正式复查已强制核对6份目标回复均纳入，未覆盖旧记录。

多楼层正文补全后的两份新回复，各复评3次，中文三次8分、英文三次10分，均通过。**这只是该案例的复查，不等于全局裁判正确率100%。**客服、支持性检查与 Judge 都来自同一 DeepSeek 网关，三次一致仍可能一致地判断错；没有独立业务人工确认。

新增的生成前支持性检查器也出现错误：把已验证的型号别名当成跨型号，并把一些本来支持的叙述列进“违规”理由。该候选已拒绝，不在当前客服中运行。它的高忠实度与较差完成率一起保留，说明不能靠叠加同源模型裁判就宣称质量提高。

## 什么才允许上传

继续保留原回归与新措辞确认集的严格双门槛。只有冻结版本在独立确认中 **Hit@1和集合Recall@1都严格大于90%**，并在预先冻结的至少60个独立问题上，用相同 Ragas 评测器比较父版和候选，忠实度均值不下降且没有缺失记录，发布检查才可能通过。

新确认集600个问题形式保持未运行。其知识来源曾见过，只能称“已知知识库上的新措辞独立确认”，不是新来源盲测或真实客户结案验证。本轮12请求的忠实度结果不替代这项确认。

当前门槛未通过，未创建提交、分支或上传，原私有仓库中的历史分支保持原样。真实问题解决率、生产CSAT、实际转人工率、重复咨询率仍没有结果标签。
